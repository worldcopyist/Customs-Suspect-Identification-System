## 先说明记录边界

当前仓库此前没有 Git 提交历史。以下较早记录来自现有源码、实施说明、测试记录和用户反馈的回溯，能说明已知目标、处理方向和当前结果，但**不能还原每一次保存、每一行改动、每个精确时间或未保留的失败尝试**。因此，本文把“已核对”“历史记录”“待验证”分开，不把历史描述写成独立验收结论。

从本文件建立后，后续每一个独立修改都应先新增一个 `CHG-NNNN` 条目，写明问题、依据、原因或尚未确认的假设、修改过程、影响、实际测试结果、回退方式和遗留项；同时更新英文手册。不要删除旧条目，应以新的更正或替代条目说明变化。

### CHG-0002：修复首次进入错误跳转到改初始密码、登录注册加载失败和 CSRF 问题

- 状态：历史已实现。
- 问题：匿名打开服务时出现“修改初始密码”，登录和注册还曾显示 `Load failed` 或接口参数错误。
- 原因判断：匿名状态与“已验证但必须改初始密码”的受限会话未充分区分；前后端对同源 Cookie、CSRF 和错误返回的处理需要统一。该判断来自历史修复记录，不是本次重新复现的网络追踪。
- 处理过程：匿名用户进入登录页；只有用正确密码完成认证、且账户被标记为首次改密时，才进入受限改密页。前端集中处理 API 请求、CSRF 初始化、一次明确的 CSRF 失效恢复及请求编号提示。
- 影响：`ui/core.js`、认证接口、会话和安全服务。
- 历史验证：隔离登录、注册、改密和匿名入口检查通过。
- 遗留：尚未做生产环境下的登录限流和多浏览器长期会话验收。

### CHG-0003：认证页面、密码可见性和个人中心改密

- 状态：历史已实现。
- 问题：需要替换认证页左侧背景、删除装饰柱体、在密码框提供眼睛按钮，并让用户可在个人中心修改密码。
- 处理过程：认证页改为背景和文字组合；密码框右侧按钮可切换明文／密文；个人中心新增改密；密码不写入日志或文档。
- 规则冲突：早期反馈要求最少 8 位，后续接口文档明确统一新密码为 12～128 位，因此当前前后端按 12 位执行。已存在的密码哈希未因该变更被重置。
- 遗留：不同浏览器的完整视觉回归尚未验收。

### CHG-0004：登录状态持久化和失效行为

- 状态：历史已实现。
- 问题：用户希望登录状态持久化，但也曾出现因空闲过期的提示。
- 处理过程：使用服务端会话 Cookie，普通会话最长 8 小时、空闲 30 分钟；账户停用、角色／权限变化、改密和退出可撤销会话。后台轮询不应无限续期；退出请求未获服务端确认时，前端不假装已安全退出。
- 风险：持久化不是永久免登录，长时间、断网和多设备场景仍需专项验收。
